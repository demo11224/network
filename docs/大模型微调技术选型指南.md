# 大模型微调技术选型指南

> 覆盖全参数训练、部分参数训练（Freeze）、LoRA、QLoRA 四种微调方式的技术原理、选型框架、数据量要求与资源约束。所有数字均来自工程实践中的典型量级，可直接用于立项评估和资源申请。

---

## 一、四种微调方式的技术本质

### 1.1 一句话定义

| 方法 | 一句话本质 | 可训练参数占比 | 基座权重精度 |
|---|---|---|---|
| 全参数训练（Full FT） | 解冻所有权重，整个模型重新学 | 100% | bf16/fp16 |
| 部分参数训练（Freeze/Partial） | 只解冻部分层，其余冻结 | 5%~30%（取决于解冻多少层） | bf16/fp16 |
| LoRA | 冻结全部原权重，旁路挂一对低秩矩阵学"增量" | 0.1%~1% | bf16/fp16 |
| QLoRA | LoRA 的省显存版：基座压成 4-bit，只有旁路是高精度 | 0.1%~1% | 4-bit（NF4） |

### 1.2 核心实现原理

#### （1）全参数训练

反向传播更新模型每一个权重。难点不在算法，在显存账：用 AdamW 优化器训练时，每个参数要存——

- 权重本身（bf16，2 字节）
- 梯度（bf16，2 字节）
- 优化器一阶动量 m（fp32，4 字节）
- 优化器二阶动量 v（fp32，4 字节）
- fp32 主权重副本（混合精度训练需要，4 字节）

合计 **约 16 字节/参数**，再加上激活值（与 batch size、序列长度成正比）。一个 7B 模型仅静态开销就约 112GB，**这就是为什么全参数微调 7B 至少要 4~8 张 80G 卡（配合 ZeRO/FSDP 切分）**，单卡根本放不下。

它的回报是：所有权重都可以动，能改变模型的"深层行为"——注入新知识、学新语言、做领域继续预训练，这些是其他方法很难替代的。

#### （2）部分参数训练（Freeze）

把大部分层 `requires_grad=False`，只训练若干层。常见三种解冻策略：

- **解冻最后 N 层 Transformer block**（最常用，对应 LLaMA-Factory 的 `freeze_trainable_layers`）：模型高层负责任务相关的抽象表示，改高层对输出行为影响最直接；
- **只解冻 embedding + lm_head**：适合扩词表、适配新语言的第一阶段；
- **只解冻 bias（BitFit 思路）**：极端省资源，现在基本被 LoRA 取代。

显存节约来自：冻结层不存梯度和优化器状态。但要注意一个常被忽略的事实：**只要可训练层不在最底层，前向激活仍要全量保存**（反向传播要穿过冻结层把梯度传到可训练层），所以激活显存省不了多少，节约幅度不如直觉中大。

#### （3）LoRA（Low-Rank Adaptation）

理论出发点：**微调引起的权重变化量 ΔW 是低秩的**——模型适配一个新任务，实际只需要在一个很小的子空间里调整。于是不直接改 W，而是旁路学一个低秩分解：

```
W' = W + (alpha/r) · B·A
其中 W ∈ R^(d×k) 冻结不动；B ∈ R^(d×r)，A ∈ R^(r×k)，r 通常取 8~128，远小于 d、k
```

以 7B 模型、r=16、挂全部线性层为例，可训练参数约 4000 万，**只占 0.6%**。梯度和优化器状态只需要为这 0.6% 维护，显存从 112GB 量级直接降到 20GB 以内。

工程上的两个关键收益：

- **训练完可以把 BA 合并（merge）回 W**，推理零额外延迟，部署和原模型完全一样；
- **不合并则可以热插拔**：一个基座 + N 个几十 MB 的 adapter，服务 N 个业务，多租户场景成本极低。

关键超参（实践默认值）：

| 超参 | 推荐值 | 说明 |
|---|---|---|
| r（秩） | 8~64 | 数据少/任务简单用 8~16；数据多/任务难用 32~64。r 翻倍≠效果翻倍，先调数据再调 r。2025 年起可用"容量算法"精确定 r（见《LoRA微调实践指南》第三章） |
| lora_alpha | 2×r | 缩放系数，固定 alpha/r=2 即可，不必单独调 |
| target_modules | **all-linear**（q,k,v,o,gate,up,down 全挂） | 早期论文只挂 q,v 是为了省事，实测全挂明显更好，这是新项目的默认正解 |
| 学习率 | 1e-4 ~ 3e-4 | **比全参数高约一个数量级**（全参数通常 1e-5~2e-5）。照搬全参数学习率是 LoRA 不收敛最常见的原因 |
| lora_dropout | 0.05~0.1 | 数据少时开，数据多可设 0 |

#### （4）QLoRA

QLoRA = **4-bit 量化基座 + LoRA**，三项核心技术：

1. **NF4 量化**（4-bit NormalFloat）：针对权重服从正态分布的特点设计的 4-bit 数据类型，比普通 int4 信息损失小；
2. **双重量化**：把量化常数本身再量化一次，每参数再省约 0.4 bit；
3. **Paged Optimizer**：显存峰值时把优化器状态换页到 CPU 内存，防 OOM。

基座以 4-bit 存储（约 0.5 字节/参数），前向/反向计算时逐块反量化为 bf16 参与运算，LoRA 旁路始终保持 bf16 精度并接收全部梯度更新。

代价两条，立项时必须知道：

- **训练速度比 LoRA 慢 30%~50%**（反量化开销）；
- **有量化误差**。论文结论是"与 16-bit 全参微调可比"，工程实测：对话/风格类任务确实几乎无损；数学、代码、复杂推理类任务比 bf16 LoRA 低 1~2 个点。**QLoRA 不是免费午餐，是"用时间和一点精度换显存"。**

### 1.3 四者的内在关联

四种方法在同一条光谱上，本质都是在回答一个问题：**给模型多少"自由度"去改变自己？**

```
全参数 ──────→ Freeze ──────→ LoRA ──────→ QLoRA
全部自由度      子集自由度      低秩子空间      低秩子空间 + 基座降精度

自由度递减 → 显存递减 → 需要的数据量递减 → 过拟合风险递减 → 能力改造上限递减
```

两条推论，是后面所有选型逻辑的根基：

1. **自由度和数据量必须匹配。** 可训练参数越多，需要越多数据去约束它，否则过拟合 + 灾难性遗忘。"数据少所以用全参数好好学"是方向完全反掉的错误直觉——数据少恰恰应该用 LoRA。
2. **任务对模型的"改造深度"决定方法下限。** 改说话风格、输出格式 → 低秩增量足够；注入新知识、学新语言 → 需要动 embedding 和大量权重，LoRA 的低秩瓶颈就不够用了。

## 二、多维度选型框架

### 2.1 按模型参数规模

| 模型规模 | 典型代表 | 首选 | 备选 | 实践要点 |
|---|---|---|---|---|
| 小（≤3B） | Qwen2.5-0.5B/1.5B/3B | **全参数** | LoRA | 小模型全参微调单卡 80G（甚至 4090 + ZeRO offload）就能跑，且小模型容量有限，LoRA 的低秩约束伤害相对更大，能全参就全参 |
| 中（7B~14B） | Qwen2.5-7B、Llama-3-8B | **LoRA** | 全参（有 8×A100 且任务需要）；QLoRA（只有消费卡） | 工业界最主流区间。90% 的业务需求 LoRA 就到位；只有知识注入/行为大改才上全参 |
| 大（30B~70B） | Qwen2.5-72B、Llama-3-70B | **LoRA（多卡）/ QLoRA（单卡 48G 或 2×24G）** | 全参（仅大规模集群） | 70B 全参微调静态显存超 1TB，需要数十张 A100 + ZeRO-3，不是一般团队的选项 |
| 超大（100B+ / MoE） | DeepSeek-V3 级别 | **QLoRA/LoRA**，或干脆不微调 | — | 这个量级先认真评估 RAG + 提示工程 + Few-shot 能不能解决，微调是最后手段 |

### 2.2 按任务类型

| 任务类型 | 推荐方法 | 理由与落地细节 |
|---|---|---|
| **分类 / 打分 / 奖励模型** | LoRA（r=8~16），数据极少时 Freeze（最后 2~4 层 + 分类头） | 输出空间小，不需要改造生成能力。注意：百条级数据时先试试不微调、直接 few-shot prompt |
| **风格 / 格式生成**（客服话术、固定 JSON 输出、文案口吻） | **LoRA，最典型的甜点场景** | 这类任务本质是"输出分布的低秩偏移"，与 LoRA 假设完全吻合。几千条数据、r=8~16、单卡几小时搞定 |
| **指令微调（通用 SFT）** | 数据 <10 万条 → LoRA（r=32~64, all-linear）；数十万条高质量数据且追求上限 → 全参数 | LLaMA-Factory 表中所有 SFT 路线四种方式都支持，瓶颈在你的数据量配不配得上自由度 |
| **领域知识注入**（医疗/法律/金融继续预训练） | **全参数 或 Freeze（高层 + embedding）**，LoRA 不推荐当主力 | "记住新知识"需要改写大量权重中的事实存储，低秩增量装不下。数据要求是 GB 级 token（见第三章）。预算不够时，正确答案是 **RAG，不是 LoRA 硬训** |
| **新语言 / 扩词表** | 必须动 embedding：全参数，或分阶段 Freeze（先只训 embedding+lm_head，再放开高层） | 任何不解冻 embedding 的方法对新 token 都无能为力 |
| **多模态微调**（LLaVA 类架构） | 分模块组合：**projector 全参 + LLM 用 LoRA + 视觉编码器冻结** | 多模态不是单选题，是按模块拆开各用各的。第一阶段对齐训练只训 projector；第二阶段指令微调时 LLM 挂 LoRA |
| **偏好对齐（DPO/KTO/ORPO/SimPO）** | **LoRA 优势特别明显** | DPO 需要策略模型 + 参考模型两份权重；LoRA 下参考模型 = 关掉 adapter 的同一基座，**直接省掉一份完整模型的显存**。这是 LoRA 在对齐训练中近乎默认的原因 |
| **PPO（RLHF）** | LoRA / QLoRA | PPO 同时挂 actor、critic、reward、reference 四个模型，全参数训练的显存是天文数字，没有 LoRA 基本玩不动 |

### 2.3 选型决策树（可直接执行）

```
Q1. 任务需要注入新知识 / 新语言 / 大幅改变模型底层能力吗？
 ├─ 是 → Q1a. 有 GB 级领域语料 + 多卡 A100 集群吗？
 │        ├─ 有 → 全参数（或 Freeze 分阶段），按继续预训练流程走
 │        └─ 没有 → 别硬训，上 RAG / 换更强基座
 └─ 否（风格、格式、指令遵循、对齐类） → Q2

Q2. 显存够把基座以 bf16 放下并留出激活空间吗？
     （经验线：模型参数量 GB 数 × 2 + 30% 余量 ≤ 单卡或合计显存）
 ├─ 够 → LoRA（默认 all-linear，r 按数据量定）
 └─ 不够 → QLoRA（接受慢 30~50% 和 1~2 个点的精度风险）

Q3.（仅当 Q2 选了 LoRA 且效果到顶仍不满足）
 数据量 ≥ 10万高质量样本，且有 8 卡级算力？
 ├─ 是 → 升级全参数，博最后 1~3 个点
 └─ 否 → 优化数据质量比换方法收益大，回去洗数据
```

## 三、数据量的量化要求

### 3.1 各方法 × 各任务的数据量阈值（指令格式样本数）

下表是工程实践中"能看到效果的下限"和"收益开始饱和的区间"，不是论文里的理想值：

| 场景 | 方法 | 最低起效量 | 舒适区间 | 饱和点 |
|---|---|---|---|---|
| 文本分类（每类） | LoRA/Freeze | 50~100 条/类 | 500~1000 条/类 | ~5000 条/类 |
| 风格/格式生成 | LoRA | 300~500 条 | 1k~5k 条 | ~1 万条 |
| 垂直领域问答（知识在 prompt/RAG 里，模型只学回答方式） | LoRA | 1k 条 | 5k~5 万条 | ~10 万条 |
| 通用指令微调 SFT | LoRA | 5k 条 | 2 万~10 万条 | 数十万条 |
| 通用指令微调 SFT | 全参数 | 1 万条（低于此过拟合风险高） | 5 万~50 万条 | 百万条级 |
| 领域知识注入（继续预训练） | 全参/Freeze | **100M token**（低于此基本无感） | 1B~10B token | 视领域而定 |
| DPO/ORPO/SimPO 偏好对 | LoRA | 2k~5k 对 | 1 万~5 万对 | ~10 万对 |
| 奖励模型 | LoRA | 5k 对 | 2 万~10 万对 | — |

两个必须记住的特例：

- **LIMA 现象**：1000 条极高质量、多样性极好的数据全参微调也能出好模型——但前提是"极高质量"，绝大多数团队自认为的高质量数据达不到，**不要拿 LIMA 当少数据上全参的理由**；
- **知识注入的 100M token 红线**：很多团队拿几万条领域 QA 做 LoRA 就期望模型"学会医疗知识"，实际只学会了"医疗腔"。知识注入是预训练级任务，几万条 QA 远远不够。

### 3.2 数据量—模型—方法的匹配关系（核心规律）

1. **数据量跟着"可训练参数量"走，不是跟着模型大小走。** 70B 模型挂 r=16 的 LoRA，可训练参数和 7B 挂 LoRA 是同一量级，所以需要的数据量也是同一量级。这是"大模型 + LoRA + 小数据"能成立的根本原因。
2. **基座越强，需要的数据越少。** 同一个任务，Qwen2.5-72B + 1k 条 LoRA 的效果，常常好于 7B + 1 万条。预算允许时，"换大基座 + 少数据 LoRA"通常优于"小基座 + 堆数据"。
3. **LoRA 的 r 与数据量挂钩**：几千条 → r=8~16；几万条 → r=32；十万条以上 → r=64 或考虑全参。数据少还开大 r，等于给了过拟合的自由度。
4. **Epoch 数与数据量反向**：<5k 条可以跑 3~5 epoch（盯紧验证集 loss，过拟合迹象立刻停）；>5 万条跑 1~2 epoch 足够；全参数几乎永远 ≤2 epoch。
5. **防遗忘配比**：做领域 SFT 时按 **领域数据 : 通用数据 ≈ 1:1 到 1:5** 掺入通用指令数据，否则模型学会了你的任务、忘掉了通用能力（全参数下尤其严重，LoRA 下也存在）。
6. **质量 > 数量，且是数量级意义上的大于**：去重、去模板化、答案正确性核验、长度和题型多样性，这四件事做好，3k 条顶得上没洗过的 3 万条。微调项目失败的第一原因永远是数据，不是方法选错。

## 四、资源消耗、速度与效果上限对比

### 4.1 训练显存需求（bf16、AdamW、batch=1、4k 上下文，含激活的工程估算）

| 模型 | 全参数 | Freeze（训 1/4 层） | LoRA | QLoRA |
|---|---|---|---|---|
| 7B | ~120GB（≥2×80G，推荐 4~8×A100） | ~55GB（1×80G） | **~18GB（1×24G，如 4090）** | **~8GB（1×12G）** |
| 14B | ~240GB（≥4×80G） | ~110GB（2×80G） | ~34GB（1×40G/48G） | ~12GB（1×16G） |
| 34B | ~600GB（8×80G+） | ~260GB（4×80G） | ~76GB（1×80G） | ~24GB（1×24G，贴边） |
| 70B | ~1.2TB（16~32×80G + ZeRO-3） | ~520GB（8×80G） | ~155GB（2×80G） | **~42GB（1×48G 或 2×24G）** |

> 速算公式：全参数 ≈ 参数量(B)×16~18 GB；LoRA ≈ 参数量(B)×2 GB + 2~6GB 激活；QLoRA ≈ 参数量(B)×0.55 GB + 2~6GB 激活。开 gradient checkpointing（默认都该开）后激活项可控；序列拉到 32k 以上时激活会反超权重项，需另行估算。

### 4.2 速度与收敛

| 维度 | 全参数 | Freeze | LoRA | QLoRA |
|---|---|---|---|---|
| 单步耗时（同卡数） | 基准 | 略快于全参 | 与全参接近（前向不省，省的是优化器更新和通信量） | **慢 30%~50%**（反量化开销） |
| 收敛所需 epoch | 最少（1~2） | 少 | 略多（用 1e-4 级学习率补偿后差距很小） | 同 LoRA |
| 多卡扩展性 | 需要 ZeRO/FSDP，通信重 | 中等 | 极好（梯度同步量只有 adapter 大小） | 极好 |
| 总训练成本（同任务同效果） | 最高（卡数 × 时间） | 中 | **最低** | 卡时单价低但时长 +30~50%，总成本通常仍低于 LoRA 多卡方案 |

### 4.3 效果上限

```
全参数 ≥ Freeze ≈ LoRA(all-linear, r 足够) > QLoRA
```

按任务拆开看（差距为典型 benchmark 分差）：

| 任务类型 | LoRA vs 全参 | QLoRA vs LoRA |
|---|---|---|
| 风格/格式/对话 | **基本无差距（<0.5 点）** | 基本无差距 |
| 通用指令遵循 | 0~1 点 | 0~1 点 |
| 数学/代码/复杂推理 | 全参领先 1~3 点 | LoRA 领先 1~2 点 |
| 知识注入/继续预训练 | **全参显著领先，LoRA 不胜任** | — |

结论：**任务越"浅"（改输出分布），方法之间越无差别；任务越"深"（改内部知识与推理），自由度高的方法优势越大。** 用差距大小反推：如果你的 LoRA 和全参在你的任务上跑出 5 个点以上的差距，先怀疑 LoRA 配置错了（学习率照搬全参、只挂了 q,v、r 太小），而不是急着下"LoRA 不行"的结论。

### 4.4 一页式速查表

| | 全参数 | Freeze | LoRA | QLoRA |
|---|---|---|---|---|
| 7B 最低硬件 | 2~8×A100-80G | 1×A100-80G | 1×4090-24G | 1×3060-12G |
| 70B 最低硬件 | 数十卡集群 | 8×A100 | 2×A100-80G | 1×48G / 2×24G |
| 最低有效数据量 | ~1 万条 | ~5k 条 | **~500 条** | ~500 条 |
| 学习率量级 | 1e-5~2e-5 | 1e-5~5e-5 | **1e-4~3e-4** | 1e-4~3e-4 |
| 效果上限 | ★★★★★ | ★★★★ | ★★★★ | ★★★☆ |
| 灾难性遗忘风险 | 高 | 中 | **低** | 低 |
| 部署复杂度 | 直接替换权重 | 直接替换 | merge 后零开销 / 不 merge 可热插拔 | 同 LoRA（merge 时注意要合到 bf16 基座上再量化，勿在 4-bit 上直接合） |
| 知识注入能力 | ★★★★★ | ★★★ | ★ | ★ |
| 典型适用 | 继续预训练、大改行为、新语言 | 扩词表过渡阶段、折中方案 | **90% 的业务微调需求** | 显存受限下的 LoRA 平替 |

## 五、常见误区（每条都来自真实踩坑）

1. **"数据少，所以用全参数好好学"** —— 反了。数据少更要用 LoRA 收紧自由度；几百条数据全参微调 = 过拟合 + 灾难性遗忘双杀。
2. **"用 LoRA 给模型灌领域知识"** —— 低秩增量装不下知识。几万条领域 QA 的 LoRA 只会让模型学会领域口吻。知识问题用 RAG 或继续预训练解决。
3. **LoRA 学习率照搬全参数的 2e-5** —— loss 几乎不降，然后得出"LoRA 没用"的错误结论。LoRA 学习率要高一个数量级。
4. **target_modules 只挂 q,v** —— 这是 2021 年论文的省事配置，今天的正确默认是 all-linear，效果差距明显。
5. **把 QLoRA 当免费午餐** —— 它慢 30~50%，复杂任务掉 1~2 个点。显存够放 bf16 基座时，直接用 LoRA。
6. **不掺通用数据做 SFT** —— 模型学会你的任务、忘了说人话。领域:通用 ≈ 1:1~1:5 掺着训。
7. **效果不好先换方法** —— 微调效果的影响排序是：**数据质量 > 基座选择 > 数据量 > 超参 > 微调方法**。方法选型只决定"能不能跑得起、上限在哪"，决定下限的永远是数据。
8. **跳过"要不要微调"这一问** —— prompt 工程 + few-shot + RAG 能解决的，不要微调。微调引入训练、评估、部署、迭代的全套维护成本，它应该是手段穷尽后的选择，不是起手式。

## 六、训练阶段 × 训练方法选型矩阵（基于权威文献）

图中（LLaMA-Factory，Zheng et al., 2024 [12]）八个训练阶段均支持四种参数策略，因为**"训练阶段"和"参数更新策略"是两个正交的维度**——前者决定 loss 怎么算（next-token、reward 排序、偏好对比），后者决定哪些参数参与更新。框架"都支持"不等于"都该用"，下面逐阶段给出论文原始做法与工程推荐，**每条结论均标注文献出处**。

### 6.1 总览矩阵

| 训练阶段 | 全参数 | Freeze | LoRA | QLoRA | 关键文献依据 |
|---|---|---|---|---|---|
| 预训练（从零） | **唯一选择** | × | × | × | 定义使然：没有可冻结的预训练权重 |
| 继续预训练（CPT） | **首选** | 折中可用 | 不胜任（即使 r=256 也追不平） | 不胜任 | Biderman et al., 2024 [10] |
| SFT | 大数据追上限 | 折中 | **默认**（高 rank 可基本追平全参） | 显存受限时用，开放生成任务有折损 | Ouyang et al., 2022 [3]；Biderman et al., 2024 [10]；Dettmers et al., 2023 [2]；Ivison et al., 2023 [11] |
| 奖励模型（RM） | Llama 2 做法 | 可行 | **默认** | 可行 | Ouyang et al., 2022 [3]；Touvron et al., 2023 [4] |
| PPO | 大厂集群做法 | 少用 | **小团队默认** | 显存极限方案 | Ouyang et al., 2022 [3]；Yao et al., 2023 [13] |
| DPO | 可行（lr 须降到 5e-7 量级） | 可行 | **默认（免参考模型，省一份权重）** | 可行 | Rafailov et al., 2023 [5]；Ivison et al., 2023 [11]；TRL 官方文档 [14] |
| KTO | 可行 | 可行 | **默认** | 可行 | Ethayarajh et al., 2024 [6] |
| ORPO | 论文原始做法 | 可行 | **默认** | 可行 | Hong et al., 2024 [7] |
| SimPO | 论文原始做法 | 可行 | **默认** | 可行 | Meng et al., 2024 [8] |

### 6.2 逐阶段说明

#### （1）预训练（Pre-Training，从零开始）

不存在选型问题：模型权重从随机初始化开始，**只能全参数训练**。Freeze/LoRA/QLoRA 的前提都是"存在一个训练好的基座可以冻结"，从零预训练时该前提不成立。LLaMA-Factory 矩阵中预训练一行的 LoRA/QLoRA 选项，实际指的是下一条——继续预训练。

####（2）继续预训练（Continued Pre-Training，领域语料增量训练）

这是**有最强文献证据反对使用 LoRA 的阶段**。Biderman et al.（2024，TMLR）[10] 在 Llama-2-7B/13B 上用约 200 亿 token 的代码和数学语料做了严格对照实验，结论：

- 继续预训练场景下，**LoRA 即使把秩拉到 r=256 也无法追平全参数**，且数据越多差距越大（代码 CPT 中，r=256 的 LoRA 用 20B token 才约等于全参数用 4B token 的效果）；
- 机理：全参数微调学到的权重扰动的秩是典型 LoRA 配置的 **10~100 倍**，"低秩假设"在需要学新能力的领域（代码、数学）不成立；
- LoRA 的真正优势是正则化：源域遗忘显著更少，强于 weight decay 和 dropout。

**工程推荐**：继续预训练用全参数；多卡不足时用 Freeze（解冻高层 + embedding）折中；不要用 LoRA/QLoRA 做知识注入主力。

####（3）指令监督微调（SFT）

- 全参数路线的奠基文献是 InstructGPT（Ouyang et al., 2022）[3]：SFT、RM、PPO 三阶段全部全参数训练；LIMA（Zhou et al., 2023）[9] 证明 1000 条极高质量数据全参 SFT 即可得到强对话模型。
- LoRA 路线：Biderman et al. [10] 发现在约 10 万条指令数据（IFT regime）下，**高秩 LoRA（r=256）可基本追平全参数**——与 CPT 的结论截然相反，这正是"SFT 用 LoRA、CPT 用全参"的文献依据。其给出的 LoRA 最佳实践：alpha=2r、**target 所有 Transformer 模块（尤其 MLP）**、认真扫学习率（1e-5~5e-4）。
- QLoRA 路线：Dettmers et al.（2023）[2] 用 4-bit NF4 + 双重量化 + paged optimizer，在单张 48GB 卡上微调 65B 模型，Guanaco 在 Vicuna 基准达到 ChatGPT 99.3% 的水平；论文同时指出**必须把 LoRA 挂到所有线性层**才能匹配全参性能。
- QLoRA 的反面证据：Tülu 2（Ivison et al., 2023）[11] 在更宽的评测集上发现 **QLoRA 在开放式生成任务上系统性落后全参数（AlpacaEval 平均差约 20%）**，整体差距随模型变大而缩小（平均 10%→3%），分类型任务（MMLU）则基本无差。
- **工程推荐**：业务 SFT 默认 LoRA（all-linear，数据多就升 r）；数十万条高质量数据且追求上限时全参；显存不够上 QLoRA，但若产品形态是开放式长文生成，对 QLoRA 的折损要有预期（Tülu 2 的教训）。

####（4）奖励模型训练（Reward Model）

- InstructGPT [3] 用全参数训练 6B 的 RM（比 175B 策略模型小得多）；Llama 2（Touvron et al., 2023）[4] 则从同尺寸 chat checkpoint 初始化、全参数训练 RM，并强调 RM 能力应与策略模型相当。
- RM 本质是判别/打分任务（输出一个标量），不需要改造生成能力，与 LoRA 的低秩假设高度兼容；DeepSpeed-Chat（Yao et al., 2023）[13] 的官方实现即提供 LoRA 训练 RM 的选项。
- **工程推荐**：LoRA（r=8~16）为默认；预算充足、追求 RLHF 整体上限时按 Llama 2 做法全参 + 同尺寸基座。

####（5）PPO（RLHF）

- 原始做法（InstructGPT [3]、Llama 2 [4]）均为全参数 PPO，但那是大厂集群。PPO 的显存结构是**四模型并存**：actor（训练）+ critic（训练）+ reward（推理）+ reference（推理），DeepSpeed-Chat [13] 对此有明确的系统描述，其混合引擎正是为这个负担设计的，并支持 LoRA 训练 actor/critic 以降低显存。
- **工程推荐**：没有集群就用 LoRA（actor/critic 各挂 adapter）；进一步受限用 QLoRA。同时要诚实评估：PPO 超参敏感、流程复杂，DPO 论文 [5] 的立论动机之一就是绕开它——小团队应优先考虑 DPO/KTO/ORPO/SimPO 这类离线方法，而不是硬上 PPO。

####（6）DPO

- 原论文（Rafailov et al., 2023）[5] 把 RLHF 转化为一个对参考模型的对比损失，免去 RM 和 PPO，但**需要一个冻结的参考模型**——全参数 DPO 时这意味着两份完整权重。
- 全参数路线的标杆是 Tülu 2 [11]：全参 DPO 稳定扩展到 70B，关键超参是**极低学习率 5e-7、β=0.1**（学习率比 SFT 再低一个数量级，照搬 SFT 学习率是全参 DPO 训崩的常见原因）。
- LoRA 路线有官方文档背书：**TRL 文档明确写明"使用 PEFT 做 DPO 时无需提供单独的参考模型，trainer 自动以关闭 adapter 的冻结基座作为参考模型"**（`ref_model=None`，内部用 `disable_adapter()` 上下文切换）[14]——直接省掉一整份模型的显存，这是 LoRA 在 DPO 中近乎默认的根本原因。
- **工程推荐**：LoRA 为默认（显存减半且实现更简单）；全参 DPO 仅在追求上限且能照 Tülu 2 的超参纪律执行时使用。

####（7）KTO

- Ethayarajh et al.（2024）[6] 基于前景理论设计损失，**只需要二元信号（这条回答好/坏），不需要成对偏好数据**，在 1B~30B 模型上验证与 DPO 相当甚至更好，且对数据不平衡（好坏样本比例失衡）更鲁棒。
- 结构上与 DPO 一样依赖参考模型，因此 TRL 的 PEFT 机制（关 adapter 当参考模型）同样适用，LoRA 的显存优势同样成立。
- **工程推荐**：当你手里只有线上点赞/点踩这类非成对反馈时选 KTO；参数策略默认 LoRA，理由同 DPO。

####（8）ORPO

- Hong et al.（2024）[7] 的核心卖点是 **monolithic（单体）**：在 SFT 的 NLL loss 上加一个 odds ratio 惩罚项，**既不需要参考模型，也不需要 SFT 预热阶段**，一步完成"SFT + 对齐"。论文在 Phi-2（2.7B）、Llama-2-7B、Mistral-7B 上全参数验证。
- 没有参考模型意味着它是偏好类方法中显存最轻的路线之一；LoRA/QLoRA 叠加使用进一步降低门槛（LLaMA-Factory 矩阵中全部支持）。
- **工程推荐**：想用一次训练替代"SFT→DPO"两阶段流水线时选 ORPO；注意它消耗的是偏好对格式的数据，但承担着 SFT 的职责，数据量要按 SFT 量级准备，不能只给几千对。

####（9）SimPO

- Meng et al.（2024）[8] 用**长度归一化的平均对数概率**作为隐式奖励，**完全无参考模型（reference-free）**，并加入目标边际 γ；在 Llama-3-8B、Mistral-7B 的 Base/Instruct 两种设置下全参数训练，效果超过 DPO。
- 两个使用前提来自论文实验设置：必须从 SFT/Instruct 模型出发（它没有 ORPO 那样的单体性质）；对超参（β、γ、学习率）较敏感，照搬论文配置是起点而非终点。
- **工程推荐**：偏好数据为成对格式、想省掉参考模型显存、且已有 SFT 模型时，SimPO 是 DPO 的轻量替代；参数策略默认 LoRA，全参亦可（其显存负担本来就只有一份模型）。

### 6.3 三条贯穿所有阶段的文献规律

1. **"学新能力"的阶段用全参，"调输出分布"的阶段用 LoRA。** CPT 追不平（Biderman [10]）、SFT 高秩可追平（Biderman [10]）、偏好优化 LoRA 是社区默认（TRL [14]）——三组证据共同指向：阶段越靠后、对权重的改造越浅，参数高效方法越无损。
2. **越靠后的阶段，学习率越低。** 全参数量级参考：CPT/SFT 1e-5~2e-5（InstructGPT [3]）→ DPO 5e-7（Tülu 2 [11]）。LoRA 在各阶段都比对应全参高约一个数量级（Biderman [10] 建议扫 1e-5~5e-4）。
3. **参考模型的有无决定了偏好阶段的显存格局。** 需要参考模型的（DPO、KTO）：LoRA 可免掉这份权重（TRL [14]）；不需要的（ORPO、SimPO）：本身就省一份模型，是低资源下做偏好对齐的优先选项（Hong [7]、Meng [8]）。

## 七、进阶专题：高频被问、容易被漏的技术点

### 7.1 训练效率工程（同样的卡，差 2~5 倍吞吐）

这些开关不改变效果，只改变速度和显存，**默认都该打开**：

| 技术 | 作用 | 怎么开 | 代价 |
|---|---|---|---|
| Gradient Checkpointing | 激活显存降 60%~80% | 各框架默认开启，确认别关 | 训练慢约 20%（重算前向） |
| FlashAttention-2 | 注意力显存从序列平方降为线性，速度提升明显 | `flash_attn: fa2` | 无，必开 |
| 样本打包（packing） | 把短样本拼接到 cutoff_len，消除 padding 浪费；短文本数据集吞吐可提升 2~5 倍 | LLaMA-Factory `packing: true` | SFT 时注意框架是否处理了跨样本注意力隔离（neat_packing） |
| ZeRO 分级 | 多卡时切分优化器状态/梯度/参数 | 单卡不用；多卡全参用 ZeRO-2 起步，放不下再 ZeRO-3；LoRA 多卡用 ZeRO-0/1 即可 | ZeRO-3 通信重，速度明显下降，放得下就别用 3 |
| Liger Kernel / Unsloth | 融合算子，显存再降 20%~50%，速度 +20%~+100% | `enable_liger_kernel: true`；Unsloth 适合单卡 LoRA/QLoRA | 个别模型结构不兼容，先小跑验证 |

排查显存的顺序口诀：**先开 checkpointing 和 FA2 → 降 batch 升梯度累积 → 缩 cutoff_len → 换 QLoRA → 最后才加卡。**

### 7.2 长上下文微调（32k/128k）

- 显存大头从权重变成激活：序列长度翻倍，激活显存大约翻倍（有 FlashAttention 时是线性），8k 以内的经验公式到 32k+ 全部失效，需重新实测。
- 扩展上下文不是直接喂长数据就行：主流做法是调大 RoPE 的 base/theta 或用 YaRN（Peng et al., 2023 [19]）做位置插值，再用少量长文本数据（几百到几千条）继续训练即可激活长上下文能力——**长上下文扩展需要的数据量远小于直觉，质量和长度分布才是关键**。
- 实操注意：长上下文 SFT 时短数据要混着训（否则短输入性能回退）；评估必须用"大海捞针"类压力测试 + 真实长文任务，不能只看 loss。

### 7.3 LoRA 家族变体：什么时候值得换

| 变体 | 改了什么 | 什么时候用 | 结论 |
|---|---|---|---|
| rsLoRA | 缩放因子从 α/r 改为 α/√r，高秩时更稳 | r ≥ 64 时 | 高秩必开，零成本 |
| DoRA（Liu et al., 2024 [18]） | 把权重分解为幅值+方向分别更新 | 低秩（r=8~16）想要更接近全参的效果 | 小幅稳定提升，训练略慢，值得试 |
| LoRA+ | 给 B 矩阵更高学习率 | 通用 | 小幅提升，实现简单 |
| PiSSA | 用 W 的主奇异值分量初始化 A、B | 收敛慢的场景 | 收敛更快，最终效果与 LoRA 接近 |
| NEFTune（Jain et al., 2023 [17]） | 训练时给 embedding 加噪声（不是 LoRA 变体，是通用正则） | SFT 数据少、容易过拟合时 | `neftune_noise_alpha: 5`，一行配置，对话类任务常有免费提升 |

原则：**先把数据和基础 LoRA 配置（all-linear、学习率、r）做对，再考虑变体**。变体带来的提升通常是 0.5~1 个点级，配置错误造成的损失是 5~10 个点级。

### 7.4 图中矩阵之外的新主流：可验证奖励 RL（GRPO / RFT）

LLaMA-Factory 那张表定格在 PPO/DPO 时代，但 2025 年以来**推理模型的标准做法是 GRPO 类算法 + 可验证奖励（RLVR）**，必须补充进选型视野：

- **RLVR 的出处与标准配方**：可验证奖励强化学习（RLVR）这一术语由 Tülu 3（Lambert et al., 2024 [24]）确立，其 **SFT → DPO → RLVR 三段式**已成为 2025~2026 年开源模型后训练的标准配方（Qwen3、DeepSeek-R1 均为此范式的变体）。
- **GRPO**（DeepSeekMath, Shao et al., 2024 [16]）：去掉 PPO 的 critic 模型，对同一 prompt 采样一组回答，用组内相对分数当优势函数——显存比 PPO 少一个模型，训练更稳，是 DeepSeek-R1（2025 [20]）背后的核心算法。
- **GSPO——2025 年后的重要演进**（Zheng et al., 2025 [23]，Qwen 团队）：Qwen 团队发现 GRPO 的 token 级重要性采样在长时间训练中会导致不可逆的模型崩塌，GSPO 改为**序列级**的重要性比与裁剪，训练效率和稳定性均优于 GRPO，并**原生解决了 MoE 模型 RL 训练的稳定性问题**（无需 Routing Replay 等补丁）——Qwen3 全系（Instruct/Coder/Thinking）即用 GSPO 训练。**选 MoE 基座做 RL 时，GSPO 是当前默认正解；稠密模型 GRPO/GSPO 均可。**
- **可验证奖励**：数学（答案对错）、代码（单元测试通过与否）、格式（正则校验）这类**能自动判分的任务，不需要训练 RM**，写个打分函数就是奖励——彻底绕开偏好标注。
- **选型规则**：你的任务若有客观对错标准（数学、代码、抽取准确率、工具调用成功率）→ 优先考虑 SFT + RLVR（GRPO/GSPO）；任务是主观偏好（语气、有用性）→ 仍走 DPO/KTO 路线。
- **框架注意**：LLaMA-Factory 本体不含 GRPO/GSPO 训练器，其官方指引（2025-07 issue #8717）是使用同作者的姊妹项目 **EasyR1**（支持 RLVR 系列与多模态 RL）；其他主流选择是 TRL（GRPOTrainer）和 veRL。
- 数据准备：GRPO/GSPO 只需要 prompt + 自动判分器，不需要人写答案；起步几千个带标准答案的题目即可。

### 7.5 灾难性遗忘的工程对策（按成本排序）

1. **掺通用数据回放（replay）**：领域:通用 ≈ 1:1~1:5，零成本，必做；
2. **用 LoRA 而非全参**：Biderman et al. [10] 证明 LoRA 的遗忘显著小于全参 + weight decay/dropout；
3. **降低学习率 / 减少 epoch**：遗忘量与更新幅度正相关；
4. **训后模型融合**：把微调模型与原模型按权重插值（如 0.7:0.3），常能用 1 个点的领域损失换回大量通用能力；
5. **训前备份评估基线**：MMLU/CEval + 通用对话盲测各跑一遍，训后对比，遗忘要量化而不是凭感觉。

## 八、学习率设置指南（论文实测数值汇编）

学习率是微调中**性价比最高的超参**：配错一个量级，轻则不收敛，重则把模型训成复读机；而配对它不花一分钱。本章所有数值来自论文原文或官方仓库，不是经验玄学。

### 8.1 先记三条总规律（所有数值都由它们推出）

**规律一：微调方法决定量级——LoRA 比全参数高约 10 倍。**

证据链：全参 SFT 的标杆值是 2e-5（Llama 2 [4]）、1e-5~2e-5（Tülu 2 [11]）；而 LoRA 论文 [1] 在 GPT-3 上用 2e-4，QLoRA 论文 [2] 官方推荐 2e-4（≤13B）/ 1e-4（33B/65B），Biderman et al. [10] 系统扫参后确认 LoRA 最优学习率比全参高约一个数量级，并建议在 1e-5~5e-4 区间扫。原因：LoRA 的 B 矩阵从零初始化、可训练参数极少，需要更大步长才能在低秩子空间里走出有效更新。

**规律二：训练阶段越靠后，学习率越低——从 SFT 到 DPO 要降 30~40 倍。**

各阶段全参标杆值串起来看：CPT/SFT 约 2e-5 → RM 约 1e-5~5e-6（Llama 2 [4]）→ PPO 约 9.65e-6（InstructGPT [3]）→ DPO/KTO/SimPO 约 5e-7~1e-6（Zephyr [21]、Tülu 2 [11]、SimPO [8]）。原因：越靠后的阶段，模型已经是"调好的"状态，偏好优化只需要微小的分布修正；SimPO 官方仓库原话——**"学习率是偏好优化最关键的超参，1e-5 这种大学习率会让模型输出语无伦次或完全重复的句子"**。新手在 DPO 阶段照搬 SFT 学习率，是偏好训练训崩的第一大原因。

**规律三：模型越大，学习率越小——每大一个数量级约减半。**

证据：Tülu 2 [11] SFT 用 2e-5（7B/13B）、1e-5（70B）；Llama 2 [4] RM 用 1e-5（小模型）、5e-6（70B）；QLoRA [2] 用 2e-4（≤13B）、1e-4（33B/65B）。大模型梯度信噪比更高、每步更新"含金量"更大，步长要相应收小。

### 8.2 主表：方法 × 阶段的学习率区间（带出处）

| 阶段 | 全参数 | LoRA / QLoRA | 数值出处 |
|---|---|---|---|
| 继续预训练 CPT | 1e-5 ~ 5e-5 | 5e-5 ~ 2e-4 | Biderman et al. [10]（代码/数学 CPT 扫参） |
| **SFT** | **1e-5 ~ 2e-5**（≤13B 取 2e-5，70B 取 1e-5） | **1e-4 ~ 2e-4**（≤13B 取 2e-4，33B+ 取 1e-4） | Llama 2 [4]：2e-5；Tülu 2 [11]：2e-5/1e-5；LIMA [9]：1e-5 线性衰减到 1e-6；QLoRA [2]：2e-4 / 1e-4 |
| 奖励模型 RM | 5e-6 ~ 1e-5（70B 取 5e-6） | ~1e-4 | Llama 2 [4]：1e-5（小）/ 5e-6（70B），warmup 3% |
| PPO | ~1e-5 量级 | 1e-5 ~ 5e-5 | InstructGPT [3]：9.65e-6（cosine），KL 系数 0.02 |
| **DPO** | **5e-7 ~ 1e-6** | **5e-6 ~ 5e-5（起点 5e-6）** | Zephyr [21]：5e-7，β=0.01；Tülu 2 [11]：5e-7，β=0.1；TRL 官方 LoRA-DPO 示例 [14]：5e-6 |
| KTO | 5e-7 ~ 1e-6 | 5e-6 ~ 5e-5 | KTO [6] 与 TRL 实践，区间同 DPO |
| ORPO | **8e-6 ~ 5e-5（注意：比 DPO 高一个量级）** | ~1e-4 | ORPO [7]：8e-6——因为它兼任 SFT，学习率按 SFT 量级走，这是它和其他偏好方法最大的超参差异 |
| SimPO | **3e-7 ~ 1e-6（官方要求网格搜索）** | 3e-6 ~ 1e-5 | SimPO 官方仓库 [8]：网格 {3e-7, 5e-7, 8e-7, 1e-6}，配 β=2.0~2.5；不同基座最优值不同（Mistral-Base 3e-7，Llama3-Instruct 1e-6） |
| GRPO / GSPO（RLVR） | ~1e-6 | 5e-6 ~ 1e-5 | DeepSeekMath [16]：1e-6；GSPO [23] 同量级 |

读表方法：**先按"方法"定列（全参还是 LoRA），再按"阶段"定行，落点取区间中位数当起点**。Freeze（部分参数）训练用全参数列的数值——它的可训练部分和全参的更新动力学一致。

### 8.3 任务维度的修正系数（在主表基础上微调）

| 任务情况 | 调整方向 | 依据 |
|---|---|---|
| 风格 / 格式 / 客服话术（与基座行为距离近） | 主表默认值即可，**不要调大**——任务简单时大学习率只会加速过拟合 | — |
| 分类 / 打分（输出空间小） | LoRA 可取区间上限甚至更高（2e-4 ~ 5e-4） | LoRA 论文 [1] 在 GLUE 分类任务上用 4e-4 ~ 5e-4 |
| 代码 / 数学 / 新能力（与基座距离远） | 全参取区间上限并配足 warmup；**LoRA 必须扫参，对学习率最敏感的正是这类任务** | Biderman et al. [10]：LoRA 在代码/数学域对学习率高度敏感，扫参是逼近全参效果的前提 |
| 推理密集任务做偏好优化 | 取区间**下限**（5e-7 甚至 3e-7） | SimPO 官方仓库 [8]：数学等推理域更小的学习率对 DPO 和 SimPO 都更合适 |
| 多模态分阶段训练 | 对齐层（projector）全参预训练用 **1e-3**；第二阶段整体指令微调回落到 **2e-5** | LLaVA-1.5 [22] 官方配置——随机初始化的 projector 是"从零训练"，遵循预训练量级而非微调量级 |
| 新语言 / 扩词表（动 embedding） | 新增 embedding 部分可单独设高学习率（1e-4 级），主体仍按主表 | 随机初始化参数与预训练参数的步长需求不同，同 LLaVA 的逻辑 |
| 数据极少（<1k 条） | 学习率取低位 + 开 NEFTune [17]，靠多 epoch 而不是大步长 | 大步长 + 小数据 = 最快的过拟合路径 |

### 8.4 配套机制：调度器、warmup、batch size（学习率不是孤立参数）

- **调度器**：cosine 衰减是各论文的绝对主流（InstructGPT [3]、Llama 2 [4] 均为 cosine）；LIMA [9] 用线性衰减。默认 cosine 不会错；
- **warmup**：比例 0.03~0.1。Llama 2 RM 用 3% [4]；阶段越敏感（DPO 系）越建议保留 warmup，防开局梯度过大；
- **batch size 与学习率联动**：偏好优化论文普遍固定有效 batch=128（SimPO [8]、Zephyr [21]）再报告学习率——你若 batch 显著更小，学习率应同向调低（可参考线性缩放，但偏好阶段建议保守）；
- **epoch 与学习率互补**：偏好优化几乎都是 1 epoch（Zephyr、SimPO、Tülu 2 DPO 均为 1）；想多学一点，加 epoch 不如保 epoch 微调学习率。

### 8.5 故障信号 → 学习率诊断（实战速查）

| 症状 | 学习率诊断 | 处理 |
|---|---|---|
| LoRA loss 几乎不降 | 用了全参量级（1e-5） | 升到 1e-4 量级（规律一） |
| 全参 SFT loss 震荡 / NaN | 用了 LoRA 量级（1e-4） | 降到 2e-5 以下；改用 bf16 |
| DPO/SimPO 后模型语无伦次、复读 | 偏好阶段学习率过大（如 1e-5） | 降到 5e-7~1e-6（SimPO 官方仓库明确警告 [8]） |
| DPO 的 rewards/accuracies 不涨 | 学习率太小或 β 太大 | 学习率上调一档（如 5e-7→1e-6）或 β 降到 0.05 |
| 训完通用能力大幅退化 | 步长过大造成遗忘 | 学习率减半重训，掺通用数据（7.5 节） |

### 8.6 一分钟决策（不想读上文就用这套默认值）

```
SFT：      LoRA 1e-4 ｜ 全参 2e-5（≤13B）/ 1e-5（≥30B）
CPT：      全参 2e-5 ｜（LoRA 不推荐做 CPT，见 6.2）
RM：       LoRA 1e-4 ｜ 全参 1e-5（70B 用 5e-6）
PPO：      1e-5
DPO/KTO：  全参 5e-7 ｜ LoRA 5e-6
ORPO：     8e-6（它按 SFT 量级走，别照 DPO 设！）
SimPO：    5e-7 起，资源够就扫 {3e-7, 5e-7, 8e-7, 1e-6}
GRPO：     1e-6
调度：     一律 cosine + warmup 0.03~0.1，偏好阶段 1 epoch
```
